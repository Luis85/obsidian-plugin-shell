## Retained release-execution milestone and closure boundaries

The selected concern is **opt-in execution of retained release operations**:
authenticated read-only discovery, resumable draft uploads, and guarded promotion
of the exact accepted remote bytes. It builds on P rather than adding another
candidate format or builder. Its implementation can advance REL-02/05–09/11 and
AC-32–34 without claiming the rest of this ledger is complete.

Acceptance must exercise a first and subsequent version; explicit full source SHA;
annotated/wrong/missing tags; paginated releases/assets and unavailable discovery;
matching partial uploads; unexpected/changed/duplicate assets; published-version
refusal; permission errors; uncertain remote outcomes; stale/changed acceptance;
source review/default-branch restrictions; and no rebuild/clobber/delete/tag move.
Verify remote content identity through authenticated server SHA-256 digests before
promotion, not merely uploader-provided labels; unavailable digests fail closed.
Capture and revalidate the local packet before authorization, then use those exact
captured bytes for every mutation. A failed or uncertain operation stops and
requires fresh discovery before a deliberate resume.

Fake-remote tests are implementation evidence, not evidence that GitHub release
permissions, native review authenticity, protected environments or a generated
repository's first/subsequent publication actually work. Untrusted PR code must
not acquire a write token; a review JSON file is not an authorization credential.
The live operation must require explicit opt-in by the maintainer. This work
authorizes no real release, tag, upload, listing, permission or protection change.

After this milestone, full template readiness still requires case-specific legacy
evidence reconciliation; remaining event-envelope metadata and item-specific native
scope; proposed analyzer metrics and measured performance/onboarding; manual/native/
device breadth matching actual support claims; executable listing readiness;
supported dependency graph closure; and explicitly authorized real first/subsequent
release qualification with repository administration verified by its owner. The
standard Actions draft/publish interface is still missing: this milestone supplies
a local CLI, and every committed workflow retains read-only permissions. Automatic
tag creation is intentionally excluded; promotion needs a separately authorized,
existing matching tag. These boundaries keep REL-05/09/11 partial.
