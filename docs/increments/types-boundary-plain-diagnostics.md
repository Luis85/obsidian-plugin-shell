# Plain compiler diagnostics in the types boundary test

<!-- Developer handoff for one pull request. `npm run dor` checks it before implementation,
`npm run dod` after it. Replace every <placeholder>; delete these comments when done. -->

## Summary

Candidate qualification on `main` fails because `[TYPES-01]` in `tooling/tests/types-boundary.checks.mjs` asserts plain `error TS6307` text, while the evidence runner sets `FORCE_COLOR=0` and TypeScript treats any non-empty `FORCE_COLOR` as a request for pretty, ANSI-colored diagnostics. The test now asks the compiler for plain diagnostics with `--pretty false`, so its assertion no longer depends on the runner's color environment.

## Outcome

`[TYPES-01]` passes under the evidence runner and the `quality` suite exactly as it does under a plain `node --test` run, and Candidate qualification's tooling evidence no longer reports it as failed.

## Scope

### In scope

- Pass `--pretty false` to the `vue-tsc -b` build in `tooling/tests/types-boundary.checks.mjs`, with a comment naming the cause.

### Out of scope

- The open Moment advisory that keeps the live security gate red, tracked in `docs/development/MOMENT-ADVISORY-EXCEPTION.md`.
- Changing how the evidence runner or the suite runner set `FORCE_COLOR`.
