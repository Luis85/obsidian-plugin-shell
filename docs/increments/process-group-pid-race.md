# Wait for a complete pid in the process-group termination test

<!-- Developer handoff for one pull request. `npm run dor` checks it before implementation,
`npm run dod` after it. Replace every <placeholder>; delete these comments when done. -->

## Summary

Candidate qualification on `main` at 768570fc failed on `[PROCESS-GROUP-04]` (3699 total, 3692 passed, 6 expected platform skips, 1 failed) after passing in the three runs before it. The test polls the grandchild pid file with `existsSync` and reads it at once, but `writeFileSync` creates the file before its bytes land; an empty read is `Number('') === 0`, and `process.kill(0, 0)` signals the test's own process group, so pid 0 always looks alive and `gone(0)` times out. The test now waits for a positive integer pid, and a new deterministic test covers the empty-file case.

## Outcome

`[PROCESS-GROUP-04]` can no longer observe pid 0 from a half-written pid file, so its result depends only on whether the hook's termination takes the process group down.

## Scope

### In scope

- A `waitForPid` helper in `tooling/tests/agent-process-group.checks.mjs` that polls until the file holds a positive integer, used by PROCESS-GROUP-04.
- `[PROCESS-GROUP-08]`: an existing but still empty pid file resolves to the pid written later, not 0.

### Out of scope
