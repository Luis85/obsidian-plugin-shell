# Run the framework tooling suites once per platform

<!-- Developer handoff for one pull request. `npm run dor` checks it before implementation,
`npm run dod` after it. Replace every <placeholder>; delete these comments when done. -->

## Summary

The complete `verify` (about 48 minutes, three quarters of it the framework tooling suites) ran in five jobs of every Release run. Two of those repeats add no platform or toolchain coverage for the tooling suites: Setup compatibility's Ubuntu Node 24.15.0 leg now runs every verify gate except the tooling suites, and the release-tier Ubuntu Showcase leg defers setup's verify and builds only what the served showcase needs.

## Outcome

Each pull request and Release run keeps one complete verify per platform (Ubuntu in Template authoring / renamed feature and, in the release tier, Candidate qualification; Windows in Showcase), while about 65 job-minutes of repeated tooling suites per Release run disappear.

## Scope

### In scope

- `.github/workflows/setup-compatibility.yml`: the Ubuntu Node 24.15.0 / npm 12 leg defers setup's verify and runs `verify --skip tooling`.
- `.github/workflows/ci.yml`: the Showcase job's Ubuntu leg defers setup's verify and runs `verify --only build,harness-build`; Windows keeps the complete verify.
- The CI scope tests and the workflow and setup documentation.

### Out of scope

- The Windows complete verify (Showcase / windows-latest), Template authoring / renamed feature and Candidate qualification, which keep the complete verify.
- Any gate, threshold or suite content; only where the tooling suites run changes.
- Sharding or parallelizing verify.
