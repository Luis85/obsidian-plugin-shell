# DOR-09 accepts the configured gate prefixes

<!-- Developer handoff for one pull request. `npm run dor` checks it before implementation,
`npm run dod` after it. Replace every <placeholder>; delete these comments when done. -->

## Summary

The Definition of Ready rule DOR-09 rejected the handoff template's own example gate, `node bin/app check --fast --base origin/main`, as an unknown gate. `gateCommand` tried the generic `node <file>` lookup first; `bin/app` is a generated, untracked launcher, so the lookup failed before the configured `commandPrefixes` (`node bin/app `, `actionlint`, `shellcheck`) were consulted. The configured prefixes are now checked first.

## Outcome

A Test plan gate that starts with a configured prefix, including the template's `node bin/app` example, passes DOR-09, while an unknown `node` script, a mistyped `npm run` script and a command outside the prefixes are still rejected with the offending line named.

## Scope

### In scope

- `gateCommand` in `src/cli/tooling/delivery/rules-ready.mjs`: consult the configured prefixes before the `node <file>` lookup.
- A rule test and two acceptance tests, one per criterion.

### Out of scope

- The configured prefix list, the rule's severity and every other Definition of Ready rule.
- Changing the handoff template or the repository documentation.
