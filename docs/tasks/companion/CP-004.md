# CP-004 — Integrate optional template preparation

## Outcome
A developer can move from a retained design to a prepared shell project using the same reviewed operations as the standalone CLI.

## Baseline and scope
Consume SH-011 through SH-014 contracts; do not implement another downloader, installer or planner in the UI. Preserve the current authoring vault as source root and the protected contained test target. An explicit user-run CLI handoff is the baseline while in-plugin execution-policy acceptance remains unresolved.

## Acceptance criteria
- [ ] Tool checks appear only when relevant; declining preparation leaves design fully usable.
- [ ] The UI reads a data-only catalog, explains compatible template versions and separates acquisition, file writes, dependency execution and deployment.
- [ ] The exact additive plan shows created, unchanged, owned-update and conflicting files while preserving design, host profiles, companion assets and unrelated source.
- [ ] The CLI handoff and returned receipts are validated against current project/input/artifact identities; stale or edited receipts do not become success evidence.
- [ ] No unapproved project code, dependency installation, security-setting change or automatic plugin enablement occurs.

## Verification
Exercise populated vaults, missing tools, local/offline artifacts, conflicting files, stale plans and interrupted preparation through real shared operations. Differentially compare CLI and companion plans; native UI state alone is not proof of completed installation.

## Evidence and handoff
Not executed. Record actual file receipts, preserved bytes, tested execution boundary and remaining policy limitations. Publication review is separate.
