# CP-001 — Convert the concept into a real shell-based companion plugin

## Outcome
Create the native companion product from the agreed concept, using the same maintained shell foundation rather than packaging the browser prototype as an application.

## Baseline and scope
**Hard entry gates:** SH-022 shell readiness and CX-007 conversion scope. Read the [architecture contract](../../architecture/COMPANION-ON-SHELL.md), [companion PRD](../../product/COMPANION-PLUGIN-PRD.md) and accepted concept baseline. Implement the product composition and first real native vertical slice; CP-002–CP-008 complete the selected features and CP-009/CP-010 qualify them.

## Acceptance criteria
- [ ] A separately identified companion builds through shell composition and registers a real Obsidian view, command and settings entry through public shell APIs.
- [ ] It mounts genuine Vue/Pinia/Nuxt UI presentation, saves one real project record through shared document/repository services, reopens it and cleans up owned resources.
- [ ] No iframe/webview of the HTML concept, concept-global store, virtual filesystem or simulated run is used as production behavior.
- [ ] Generic persistence, events, feedback, styles, operations and lifecycle are reused, not privately copied or reimplemented; gaps return to the shell lane.
- [ ] Independent shell consumers still build, and exported templates contain no companion runtime imports or hidden dependency.

## Verification
Build/install only in an isolated native fixture, exercise mount/save/reopen/unload with real services, run shell/consumer regressions and inspect the import graph. Track unported features explicitly; a native boot is not full conversion completion.

## Evidence and handoff
Not executed. Record foundation/concept revisions, product identity, native artifact and actual results. This task implements a real product foundation but neither freezes remaining feature development nor authorizes publishing.
