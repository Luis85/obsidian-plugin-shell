# CP-002 — Persist and resume canonical design records

## Outcome
The native companion retains one project and its authored design in Markdown through the shared shell services, without requiring a developer toolchain.

## Baseline and scope
Use the [single-vault contract](../../concepts/companion/SINGLE-VAULT.md), accepted CX-007 scope and SH-004/SH-005/SH-015 APIs. Replace concept storage authority with typed records and projections. Keep presentation preferences and machine-local operation approvals separate from portable project data.

## Acceptance criteria
- [ ] Define, save, close and reopen the same project without external Node/npm/Git; existing identity and references remain stable.
- [ ] Requirements and supported design records use configured safe authoring folders and preserve handwritten bodies and unrelated frontmatter.
- [ ] Multiple leaves share committed data but retain independent drafts; external note edits refresh projections or expose an explicit conflict.
- [ ] Duplicate descriptors, future schemas, invalid references and uncertain writes preserve original data and expose recovery instead of creating a replacement project.
- [ ] Disabling or removing the companion never deletes project notes or source; moved vaults invalidate machine-local approvals without changing project ownership.

## Verification
Use real repositories and native restart/external-edit scenarios, exact Markdown assertions, duplicate/future-schema fixtures and multiple leaves. Verify no second editable project database or parallel saveData writer exists.

## Evidence and handoff
Not executed. Record source/schema revisions, exact persisted fixtures, actual native results and unsupported record types. Concept storage tests do not satisfy this task.
