# CP-006 — Integrate native source and test-data workflows

## Outcome
Developers configure, preview and deliberately provision repeatable test data for the sources used by their generated plugin.

## Baseline and scope
Implement the accepted CX-004 interactions using SH-008/SH-009/SH-010. Each supported source kind exposes its declared simulation or isolated provision mode. Production connections and credentials remain separate from design metadata and test providers.

## Acceptance criteria
- [ ] Source operations, shapes and usages are shared with generation; test scenarios record seed, clock, locale, counts, constraints and generator versions.
- [ ] Preview reports actual destinations and mode before apply; unsupported constraints/providers produce actionable errors rather than fabricated data.
- [ ] Materialization and reset use the shared ownership manifest, preserving authoring notes, unrelated test records and user-edited fixtures.
- [ ] The generated plugin reads the resulting data through its intended adapter; unavailable production adapters never silently use mocks.
- [ ] Cancelled, partial and stale operations retain drafts and honest receipts; no external service is seeded by default.

## Verification
Exercise vault, API-simulation and logical-database-simulation examples within supported modes, deterministic reruns, invalid constraints, edited fixtures and interrupted writes. Confirm the contained test-vault boundary and actual plugin-read behavior.

## Evidence and handoff
Not executed. Record provider matrix, fixture identities, write/reset receipts and actual native interactions. Do not imply that a declared database or drawn connection is a live integration.
