# CP-009 — Qualify native journeys and standalone regressions

## Outcome
Actual native evidence demonstrates the companion's accepted scope and proves it has not compromised standalone shell consumers.

## Baseline and scope
Use the accepted CX-007 scope plus reviewed changes, SH-022 baseline and current [test strategy](../../testing/TEST-STRATEGY.md). Keep model, browser, filesystem, generated-consumer, real-host, manual accessibility and performance evidence distinct.

## Acceptance criteria
- [ ] Design-only journey saves/reopens a project without external developer tools and reconciles an external Markdown edit.
- [ ] Design-to-plugin journey generates, builds and deliberately enables the reference plugin, then exercises actual note operations and failure feedback.
- [ ] Developer-ownership journey preserves customized code, adds a feature and continues with CLI after companion removal.
- [ ] Declared Windows/macOS/Linux and minimum/selected-current host combinations have actual results or explicit blocking gaps; independent shell consumers regress successfully.
- [ ] Keyboard/non-drag/focus, assistive technology, narrow panes, graph scale, startup and repeated open/close resource behavior are assessed with recorded methods and budgets.

## Verification
Run the candidate's real component and native suites, adversarial filesystem/input cases, seeded fixtures and export regressions. Perform formative usability/manual accessibility sessions and report findings without invented completion statistics or telemetry.

## Evidence and handoff
Not executed. Record exact candidate/host/tool/device identities, measured limits, observed outcomes and remaining blockers. Concept assertion totals do not count as native journeys.
