# CP-005 — Generate a working plugin from the native design

## Outcome
The native companion drives the already qualified shared compiler to create the bounded working reference plugin from authored design records.

## Baseline and scope
Reuse SH-017/SH-018 and the independent SH-019 Tasks fixture. Include one native container, internal list/editor, Task entity, vault operations, actions, settings and tests. The companion is a client of shared tooling, not another code generator.

## Acceptance criteria
- [ ] Generation uses selected scope and dependency closure, showing supported scaffolds, contract-only outputs, manual obligations and blockers.
- [ ] Review and apply refer to the same exact files and ownership plan; unsupported design elements are never silently dropped.
- [ ] The generated plugin compiles and creates/reads/updates actual notes in the contained test vault after deliberate user enablement.
- [ ] Customized generated code survives layout changes and additive feature generation; semantic drift and incompatible updates are explicit.
- [ ] Source, built candidate, installed candidate and observed native behavior remain separate evidence states.

## Verification
Run the full native design-to-reference-plugin journey, generated tests and real host checks. Compare output with equivalent standalone CLI input. Include a missing mapping, custom-code conflict, failed build and stale review.

## Evidence and handoff
Not executed. Record design/compiler/template revisions, actual output/candidate hashes, commands and native outcomes. A source preview or simulated receipt is insufficient.
