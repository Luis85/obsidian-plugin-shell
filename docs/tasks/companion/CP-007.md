# CP-007 — Integrate native design-system authoring and export

## Outcome
The companion edits the designed plugin's token model and exports consistent Markdown/HTML documentation through the reusable shell exporters.

## Baseline and scope
Implement CX-005 using SH-007 and canonical project persistence. Support the accepted typography, spacing, size, color, alias and semantic-token scope. Keep the designed consumer's tokens separate from the companion's own host styling.

## Acceptance criteria
- [ ] Editing, preview and persistence use one versioned token model; invalid values and alias cycles retain the draft with useful errors.
- [ ] Native Markdown and HTML exports match equivalent standalone exporter output for the same model and version.
- [ ] Export destinations and collisions are reviewed; user-authored files are not silently overwritten.
- [ ] HTML escapes project text, works offline and contains no downloaded fonts, font binaries or unrelated host CSS.
- [ ] Light/dark examples and token overrides do not mutate unrelated host views or imply an accessibility certification.

## Verification
Test actual token persistence, reopen/external-edit conflicts, export semantic parity, hostile text, invalid aliases and destination ownership. Exercise native dialogs and keyboard/focus behavior separately from concept snapshots.

## Evidence and handoff
Not executed. Record token/export schema versions, output hashes and actual native results. Generic fixes belong in SH-007 with standalone regressions before companion adoption.
