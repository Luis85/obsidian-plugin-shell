# SH-009 — Generate deterministic schema-driven test data

## Outcome
A standalone developer can derive valid, repeatable test data and simulated operation behavior from each supported source contract.

## Baseline and scope
Build on SH-008 and existing seeded test practices. Define generator descriptors for seed, fixed clock, locale, versions, counts, constraints and relationship references. A pinned Faker library is optional; arbitrary executable expressions in design files are not.

## Acceptance criteria
- [ ] Identical schema/generator version, seed, clock and locale yield identical output; different scenarios are explicitly selected.
- [ ] Supported required fields, ranges, enums, uniqueness and cross-record references are satisfied or generation fails with a useful unsupported-constraint report.
- [ ] Source-kind coverage declares real contained fixtures, in-process simulation or another explicitly supported isolated mode; no source silently disappears from the matrix.
- [ ] Empty, error, latency and edge-data scenarios exercise the same operation contracts as production adapters; test providers never become an automatic production fallback.

## Verification
Use property/contract tests and reproducibility snapshots with multiple seeds, relationship cycles, impossible constraints and invalid schemas. Verify library/locale/version changes invalidate the relevant fixture identity. No real vault or external service is written in this pure-generation task.

## Evidence and handoff
Not executed. Record supported constraints, source modes and actual reproducibility results. SH-010 separately controls materialization and reset.
