# SH-005 — Provide shared settings and safe path configuration

## Outcome
Standalone and companion consumers configure supported settings and entity folders through one validated service.

## Baseline and scope
Inspect existing preference/boolean setting controllers, [authoring tools](../../development/AUTHORING-TOOLS.md) and setup identity rules. Add only input types needed by accepted consumer requirements, including safe project-relative entity paths. Reconcile the requested `.test-vault` wording with the current `.dev-vault` contract without silently renaming it.

## Acceptance criteria
- [ ] Native settings and consumer views read/write the same committed projection; reads do not create records.
- [ ] Configured paths reject traversal, protected host profiles, source/runtime overlaps and ambiguous destinations; actual config-directory discovery is retained.
- [ ] Defaults, schema upgrades and invalid/future data preserve existing values and expose repair states.
- [ ] Changing a folder setting does not silently move existing records; any migration is a separate reviewed operation.

## Verification
Test supported control types, concurrent edits, focus-preserving external updates, native tab reopen/disposal and path matrices. Existing installer targets remain unchanged unless a separate reviewed extension is accepted and qualified.

## Evidence and handoff
Not executed. Document configuration ownership, supported field types, path semantics and exact migration/native results.
