# SH-014 — Prepare a populated project additively

## Outcome
The shared CLI can add the shell template to an already authored project without replacing its notes, identity or host configuration.

## Baseline and scope
Implement the native shared contract behind [single-vault preparation](../../concepts/companion/SINGLE-VAULT.md), using SH-012 and the qualified SH-013 artifact. Staging/acquisition is separate from dry-run planning and execution approval.

## Acceptance criteria
- [ ] Artifact identity, finite manifest, archive bounds and safe extraction are checked before project-root writes.
- [ ] The plan classifies create/unchanged/owned-update/conflict entries and protects actual host profiles, companion assets, Git metadata and authored design.
- [ ] Differing README/package/ignore files are not blindly overwritten; case aliases, links, overlaps and changed preimages fail safely.
- [ ] Existing project identity and design remain unchanged; repeated preparation does not create another project or erase work.
- [ ] An interrupted operation retains honest receipts and ownership-aware recovery; offline/local artifact use has explicit limits.

## Verification
Use populated filesystem fixtures, alternate config directories, malicious/oversized archives, stale approvals, no-op reruns and mid-run edits. Run real shared CLI behavior, not virtual concept files.

## Evidence and handoff
Not executed. Record exact changed/preserved bytes and actual checks. Dependency execution and any future in-plugin policy approval remain separate boundaries.
