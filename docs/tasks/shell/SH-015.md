# SH-015 — Define versioned design interchange contracts

## Outcome
A validated framework-free design snapshot can be exchanged by the concept, CLI compiler and future native companion without sharing UI state.

## Baseline and scope
Inspect [single-vault records](../../concepts/companion/SINGLE-VAULT.md), semantic entities, components and source-operation contracts. Define durable IDs, project ownership, native containers/internal screens, actions, relationships, tokens and fixture descriptors as supported schema modules.

## Acceptance criteria
- [ ] Cross-references, record kinds, ownership and size/depth limits validate before rendering or generation.
- [ ] Unfinished drafts remain representable while generation blocks only required undeclared semantics.
- [ ] Version migrations and future/invalid documents preserve original data with explicit repair/export paths.
- [ ] Semantic projection excludes viewport/selection/layout-only state; imported roots, credentials and approvals confer no execution authority.

## Verification
Test schema round trips, invalid references, duplicate IDs, malformed payloads, hostile text, migration fixtures and deterministic normalized output. Use distinct business-design fixtures rather than one hard-coded Task case.

## Evidence and handoff
Not executed. Record schemas, compatibility policy, actual contract tests and explicitly unsupported shapes. Coordinate with continuing concept work; this schema is not a declaration of feature completion.
