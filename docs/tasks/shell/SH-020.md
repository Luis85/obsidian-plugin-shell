# SH-020 — Qualify reusable host UX and performance

## Outcome
The shell's shared controls, lifecycle and styles provide a usable, measured basis for standalone plugins and the future companion.

## Baseline and scope
Use the real-component harness, [test strategy](../../testing/TEST-STRATEGY.md), [performance qualification](../../testing/PERFORMANCE-QUALIFICATION.md) and retained native protocols. Do not claim concept graph performance from shell-only tests.

## Acceptance criteria
- [ ] Keyboard/focus, non-drag alternatives where relevant, labels/errors, narrow panes, zoom and light/dark styling are exercised using shared components.
- [ ] Real native minimum/selected-current hosts on the declared Windows/macOS/Linux matrix have explicit evidence or visible blockers.
- [ ] Startup, first view open, repeated open/close and resource ownership are measured with specified hardware/fixtures and calibrated budgets.
- [ ] Portals, menus, dialogs and header preferences do not leak styles or resources into unrelated host views.

## Verification
Run automated harness/native regressions plus named manual accessibility checks. Preserve independent scope labels, failed attempts and environment restrictions. Existing gates are not weakened to obtain a pass.

## Evidence and handoff
Not executed. Record host/tool/device versions, actual measurements, manual findings and supported limits. Companion graph-specific qualification remains CP-009.
