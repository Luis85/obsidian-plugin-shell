# SH-012 — Unify reviewed operations and recovery

## Outcome
CLI and future UI execute the same reviewed plans with shared ownership, cancellation and truthful receipts.

## Baseline and scope
Extend the existing [safe maker plans](../../development/AUTHORING-TOOLS.md) and [setup contract](../../development/SETUP-IDENTITY.md), including current locks and preimage checks. Do not create another installer or free-form shell console.

## Acceptance criteria
- [ ] Plans bind operation/input versions, artifact, tools, target and exact preimages; stale inputs reject execution before subsequent mutation.
- [ ] CLI and a contract-level UI client coordinate one operation owner/lock and produce equivalent plans/results.
- [ ] Acquisition, writes, script execution and deployment expose separate side effects; process arguments and environment/log policies are explicit.
- [ ] Cancellation and recovery preserve completed work and external edits; unknown outcomes remain inspect-required rather than automatically retried.
- [ ] Imported/synced plans never carry valid machine-local authorization; output and journals are bounded and redacted.

## Verification
Exercise concurrent clients, stale approvals, partial writes, subprocess failure/timeout, hostile path/text inputs and edited recovery targets. Prove restoration only touches operation-owned bytes. Document non-atomic and non-reversible boundaries.

## Evidence and handoff
Not executed. Record plan/protocol versions, differential tests, native process/platform gaps and exact recovery outcomes. Public execution-policy approval is separate.
