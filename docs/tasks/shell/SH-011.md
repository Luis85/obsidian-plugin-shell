# SH-011 — Expose a data-only capability and operation protocol

## Outcome
CLI and future companion discover supported operations from one versioned contract rather than duplicate command lists.

## Baseline and scope
Inspect [authoring tools](../../development/AUTHORING-TOOLS.md), setup/maker metadata and current JSON output. Describe input schemas, supported outputs, prerequisites, side-effect classes, network needs, implementation status and compatibility. Preserve existing CLI entry points.

## Acceptance criteria
- [ ] The catalog matches actual registered makers/operations; drift and duplicate aliases are detected.
- [ ] Reading catalog metadata does not execute arbitrary consumer configuration, custom recipes or project scripts.
- [ ] Request/progress/result/error/receipt shapes have version rules, stable IDs and documented unknown-version behavior.
- [ ] Unsupported capabilities are visible and cannot be advertised as operational merely because a form can be rendered.

## Verification
Run schema and catalog parity tests, malformed/future-protocol fixtures and no-side-effect discovery probes. Distinguish read-only data discovery from explicitly trusted execution of local custom recipes. Test existing CLI compatibility.

## Evidence and handoff
Implemented for review: [protocol and compatibility](../../development/OPERATION-PROTOCOL.md), [actual commands, tests and limits](../../testing/preconversion-gauntlet/SH-011.md). Discovery is real and data-only; write execution is explicitly not implemented by this protocol. Current-head pinned-toolchain maker/consumer verification and independent review remain required before closing this task.
