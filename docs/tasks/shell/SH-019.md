# SH-019 — Prove an independent generated reference plugin

## Outcome
The shell alone turns a bounded design into a useful, tested plugin without a native companion or maintainer checkout.

## Baseline and scope
Use a fresh exported template and a Tasks design with one native container, internal list/editor, Task schema, active-vault operations, settings and tests. Also retain a distinct non-Task/minimal consumer to expose hard-coded behavior.

## Acceptance criteria
- [ ] CLI preparation/generation/build/verification succeeds from an independent Git-free source export under the qualified environment.
- [ ] The generated plugin opens in the contained test vault and creates/reads/updates actual notes; errors preserve drafts and existing content.
- [ ] Seeded fixtures are consumed through the declared source adapter, not an unrelated display-only dataset.
- [ ] After removing companion/maintainer dependencies, development and additive generation still work; custom source survives.
- [ ] Native installation is separate from manual enablement; no personal vault or global environment is altered.

## Verification
Record exact source and candidate hashes, actual CLI/consumer tests and real native steps. Scan exports/imports for workspace-only references, companion code, secrets and concept assets. Keep skipped platform modes visible.

Not executed. Provide reproducible independent-consumer fixtures and result packets. This is an internal shell proof, not a public release.
