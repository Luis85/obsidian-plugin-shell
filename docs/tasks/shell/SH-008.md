# SH-008 — Define executable source-operation contracts

## Outcome
Consumers use explicit data-source ports with interchangeable production/test implementations and a qualified active-vault reference adapter.

## Baseline and scope
Translate the [Data Sources contract](../../concepts/companion/DATA-SOURCES.md) into reusable framework-free types and adapter boundaries. Keep sources, operations and usages separate; reuse existing repositories for vault behavior. External APIs/databases may remain contract-only where implementation is not accepted.

## Acceptance criteria
- [ ] Inputs, outputs, direction, errors, cancellation and supported validation are explicit per operation.
- [ ] Active-vault create/read/update behavior uses shared document services and preserves unrelated data.
- [ ] Production, simulation and isolated-fixture modes are distinguishable; unconfigured adapters fail explicitly without hidden fake data or successful no-op writes.
- [ ] Credentials remain references in portable contracts; mappings and synchronization are never inferred from labels/arrows.

## Verification
Run one contract suite against the real vault adapter and a deterministic fake; test validation, conflicts, cancellation and unsupported operations. Verify adapter/platform declarations and prohibit accidental external calls during contract discovery.

## Evidence and handoff
Not executed. Record operation schemas, supported adapter matrix, actual vault results and remaining external implementation obligations.
