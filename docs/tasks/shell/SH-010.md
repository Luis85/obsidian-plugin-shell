## Outcome

## Baseline and scope
Combine SH-009 providers with shared paths/repositories and the existing contained `.dev-vault` deployment boundary. The requested `.test-vault` naming must be reconciled explicitly; do not create an alternate unguarded target. Real external-service seeding is excluded by default.

## Acceptance criteria
- [ ] A dry-run displays exact fixture destinations, source-operation mode, record count and ownership without writing.

- [ ] Reset removes/restores only verified operation-owned fixtures; user-edited or preexisting records are preserved and reported.
- [ ] Cancellation, partial writes, stale plans and repeat runs retain receipts and a safe inspect/recovery path.

## Verification
Exercise fresh and populated isolated vaults, collision/Unicode paths, symlinks, edited fixture records, interrupted writes and exact reruns. Confirm the generated reference plugin actually reads the provisioned data through its intended adapter.
