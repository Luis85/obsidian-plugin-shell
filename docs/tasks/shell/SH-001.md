# SH-001 — Reconcile shell capabilities and evidence

## Outcome
A current, evidence-linked gap inventory defines what the shell must deliver before the companion can consume it.

## Baseline and scope
Inspect the [parent PRD](../../product/PRD.md), [readiness ledger](../../development/TEMPLATE-READINESS-LEDGER.md), [authoring tools](../../development/AUTHORING-TOOLS.md), public API, scripts and current tests. Retain every applicable existing requirement and acceptance row. Distinguish implemented, partially qualified, missing and externally blocked behavior. Record distribution/policy risks without executing publication work.

## Acceptance criteria
- [ ] Each required shell capability identifies current symbols, relevant tests, evidence scope and remaining work; old maker counts do not cause duplicate implementation.
- [ ] Runtime/standalone blockers are distinguished from publication-only work without moving safety or compatibility requirements out of the shell gate.
- [ ] Every gap maps to a task; proposed concept dependencies remain requirements, not implementation evidence.
- [ ] Existing acceptance IDs, quality floors and unresolved dependency/native restrictions remain visible.

## Verification
Review source-to-requirement and requirement-to-task coverage. Reproduce disputed evidence with named checks where available; report unavailable environments honestly. Confirm no source or release behavior was changed merely to close the inventory.

## Evidence and handoff
Not executed. Record inspected commit, inventory links, observed commands/results and unresolved scope. This task is the first scheduling entry point; it does not certify the shell.
