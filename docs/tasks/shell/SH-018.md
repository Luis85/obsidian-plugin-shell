# SH-018 — Preserve generated-code ownership and explain drift

## Outcome
Developers safely rerun or extend generation without losing custom code, and can distinguish semantic drift from harmless layout edits.

## Baseline and scope
Extend existing safe-plan ownership and SH-017 mappings. Record design IDs, file ownership, original generated hashes, template/compiler versions and actual checks. Keep template upgrades and runtime-data migrations separate.

## Acceptance criteria
- [ ] First generation and identical reruns are safe; additive feature generation preserves customized and unrelated files.
- [ ] A supported managed update requires matching preimages and review; no force-overwrite escape hatch exists.
- [ ] Semantic changes identify affected files/actions/tests, while card movement, zoom and selection do not mark code stale.
- [ ] Interrupted generation and external edits produce inspectable receipts and bounded recovery rather than fabricated success.

## Verification
Customize a generated component, change layout, add another feature, alter an entity contract and interrupt apply. Assert exact preservation, conflict classification, registration integrity and receipt freshness. Exercise both CLI and protocol clients.

## Evidence and handoff
Not executed. Record ownership format, qualified update cases and exact failure outcomes. Do not advertise arbitrary two-way synchronization or automatic code merging.
