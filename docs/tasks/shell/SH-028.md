# SH-028 — Integrate full project generation with shared makers

## Outcome
An imported project definition creates coherent, editable plugin boilerplate using the same recipes as individual CLI makers.

## Baseline and scope
Integrate the semantic compiler and ownership engine into project generation. Generate supported identity/bootstrap, entities, views/components, actions/settings/source bindings, styles, tests and build tooling. The full self-project is an intake/coverage fixture, not an implied finished companion.

## Acceptance criteria
- [ ] Selected design IDs map to deterministic outputs and explicit implemented/scaffolded/manual/unsupported/blocked findings; no design element disappears silently.
- [ ] Source/tests folder settings propagate through build, typecheck, test, lint, harness, registries, imports and ownership; changing a path later requires a migration plan.
- [ ] Individual make and project generation use the identical shared services and emit compatible plans; layout-only edits leave semantic output stable.
- [ ] Plan application revalidates root, config/input/template versions and preimages; repeats are idempotent and developer/foreign edits remain preserved.
- [ ] Generated tests exercise real behavior; unfinished source/tests are reported as obligations rather than passing acceptance placeholders.
- [ ] Tasks and a distinct non-Task design produce useful built/tested consumers outside the maintainer tree; legacy handoff remains exact-byte read-only.

## Verification
Compile actual generated outputs, run their tests, compare individual maker/full-project parity, exercise custom directories and conflict/stale/unsupported cases; bind output hashes to design IDs.
