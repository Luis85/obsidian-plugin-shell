# SH-029 — Unify development, test-vault and lifecycle commands

## Outcome
The central CLI supports daily build/test/verification and isolated installation/fixtures without a companion.

## Baseline and scope
Reuse bundling, verification, installer, test-data and evidence services. Port/extract real kit logic where needed; do not copy the concept global state. Keep optional native-control adapters separate from offline project commands.

## Acceptance criteria
- [ ] Build/test/verify aliases share typed handlers and preserve exit status, cancellation and last-good complete artifacts without recursive npm delegation.
- [ ] Only approved contained test-vault targets are written; actual config directories, data.json, unrelated notes/plugins and security settings are preserved.
- [ ] Installation is not activation; no automatic Restricted Mode changes. Native absence is blocked/not-run for required native checks.
- [ ] Fixtures use declared source adapters and owned reset receipts; memory/HTTP simulations never silently substitute for production providers.
- [ ] Status and diagnostics stay read-only; runtime control has an explicit vault/plugin target and capability checks with user-run handoff fallback.
- [ ] Shared result/evidence labels distinguish unit/filesystem/harness/generated/native scope and do not turn skipped tests into passed results.

## Verification
Run CLI subprocess and faulty child-process tests, isolated native installation checks, fixture apply/reset preservation, source-adapter wiring and default/custom test-vault scenarios.

## Evidence and handoff
Not executed. Record exact commits/artifacts, commands/results, environment and remaining scope. Documentation is not implementation evidence or execution authorization.
