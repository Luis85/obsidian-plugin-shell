# SH-003 — Qualify shared host-view lifecycle

## Outcome
Standalone consumers can own multiple Obsidian views safely, providing the lifecycle foundation the companion will reuse.

## Baseline and scope
Inspect native view adapters, [presentation structure](../../development/PRESENTATION-STRUCTURE.md), [commands](../../development/COMMANDS-AND-RIBBON.md) and current lifecycle evidence. Cover normal leaves, restored leaves and supported pop-outs; retain host-owned navigation and existing header restoration behavior.

## Acceptance criteria
- [ ] Each mounted view owns drafts, portals and subscriptions while sharing the intended runtime services.
- [ ] Repeated opening, closing, plugin disable and failed initialization dispose owned resources and ignore late completions.
- [ ] One consumer's commands/header settings never alter another consumer or unrelated host leaves.
- [ ] No manual leaf detachment or global application reset is introduced.

## Verification
Use real services in adapter tests; separately run native multiple-leaf, restart and repeated-disposal scenarios. Include a pending operation during unmount and ownership/leak diagnostics. Mocked-host success is not native evidence.

## Evidence and handoff
Not executed. Record host/platform versions, exact scenarios, resource observations and missing modes. SH-020 performs broader interaction/performance qualification using this foundation.
