# SH-007 — Add reusable design tokens and documentation export

## Outcome
A standalone consumer defines a design system and exports it to Markdown or self-contained HTML without needing the companion editor.

## Baseline and scope
Extend the [modular styles pipeline](../../architecture/STYLES.md) and [host token guide](../../design/OBSIDIAN-TOKENS.md). Define a versioned model for typography, sizes, spacing, colors and supported semantic/component tokens. Keep the companion's host-integrated styling separate from a designed consumer's token values.

## Acceptance criteria
- [ ] Token validation, aliases and host-theme fallbacks are explicit; cycles/unsupported shapes produce actionable errors.
- [ ] Markdown and HTML exports represent the same token model deterministically, including examples and unsupported-value diagnostics.
- [ ] HTML escapes user text and works offline; neither export downloads fonts or includes host-extracted styles/font binaries.
- [ ] Scoped CSS composition preserves light/dark themes, namespace isolation and the no-global-reset rule.

## Verification
Round-trip representative token fixtures; compare exporter semantics; test hostile text, alias cycles and theme fallback. Build two independent consumer styles and verify isolation in the harness. Export checks do not constitute accessibility certification.

## Evidence and handoff
Not executed. Record token schema/export API, fixtures, generated output hashes and actual results. CX-005/CP-007 design and integrate the editor later.
