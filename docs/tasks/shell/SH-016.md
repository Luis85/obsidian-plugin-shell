# SH-016 — Extend makers for real designed structures

## Outcome
Existing generators accept supported consumer fields and distinguish native containers from internal screens and embedded components.

## Baseline and scope
Reuse the actual [maker catalog](../../development/AUTHORING-TOOLS.md), primitives and structural registration edits. Preserve current feature/entity/view/component/store/usecase/command/modal/setting/event/listener/style/locale/custom recipe contracts. Do not build a second generator for the companion.

## Acceptance criteria
- [ ] Supported entity fields/defaults/document mappings are reflected in generated types, runtime behavior and tests, not reduced to a fixed example preset.
- [ ] Native containers receive native registration; internal screens/components receive only their declared composition and inputs/events.
- [ ] Generated actions, settings, styles and registrations use public APIs and explicit ownership.
- [ ] Existing CLI recipes and independent custom makers still work; unsupported parameters and conflicts reject safely.

## Verification
Generate at least two distinct schemas and a container with multiple internal screens. Compile and exercise resulting code; check exact registration count, field persistence, no-op reruns, edited-file rejection and preserved user entries. Run all existing maker regressions.

## Evidence and handoff
Not executed. Record supported mapping matrix, generated artifacts and actual consumer tests. Broader unrestricted UI generation remains outside this task.
