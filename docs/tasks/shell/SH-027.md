# SH-027 — Implement guided setup and project JSON intake

## Outcome
A user configures the extracted project and imports its design without requiring an installed plugin or an Obsidian vault.

## Baseline and scope
Implement setup as a resumable coordinator over explicit configure/import/plan/apply/install operations. Adopt project-root semantics for new operations; preserve the old vault-relative read-only handoff. Defaults are src/tests and .test-vault for new kits; existing .dev-vault projects remain unchanged.

## Acceptance criteria
- [ ] Human wizard and noninteractive structured input share operations; no npm install/prepare hook invokes an interactive wizard.
- [ ] Configured/imported identity and folder conflicts are reviewed; automation must specify a resolution policy. Manifest identity is not silently replaced.
- [ ] Import accepts the current full envelope and validates nested contracts; it preserves original invalid/future input and never executes JSON, URLs, scripts or approvals.
- [ ] Portable configuration and ignored machine-local paths are separate; config explain identifies provenance; source root, authoring vault and contained test environment are distinct.
- [ ] Resume checks hashes and actual state; cancellation/failed install retains truthful checkpoints, last-good files and repair guidance.
- [ ] Exact dependency installation uses a matching qualified lockfile; intentional dependency changes require explicit resolution and a reviewed new lockfile, not silent latest.

## Verification
Run clean/direct/npm and no-TTY intake fixtures, conflicting configs, default/custom paths, old .dev-vault preservation, invalid/future exports, missing tools, interrupted setup and reruns.
