# SH-031 — Expose generated-plugin release preparation and rehearsal

## Outcome
The first framework can prepare, check, rehearse and deliberately publish a generated plugin independently of companion delivery.

## Baseline and scope
Reuse existing candidate/rehearsal/guarded release services. This task implements/qualifies capability; public side effects are not part of automated acceptance. Framework-kit publication is SH-034; companion publication remains PUB.

## Acceptance criteria
- [ ] CLI release preparation identifies exact source, tests, versions and main.js/manifest.json/optional styles.css; no unverified rebuild replaces the candidate.
- [ ] Source repository initialization/push, tag creation, draft upload, promotion and directory submission have distinct effects and approvals; existing matching-tag requirement is preserved.
- [ ] Release checks block unresolved generation obligations, missing required evidence, wrong tag/manifest versions, unsupported dependencies and leaked secrets/private design or vault state.
- [ ] First and subsequent release rehearsals exercise failures, retry-safe draft handling and uncertain outcomes without creating public releases.
- [ ] GitHub availability and Obsidian community listing are different statuses; current policy is verified and manual/unsupported submission steps are explicit.

## Verification
Exercise real candidate packaging plus controlled remote-adapter tests and negative controls. Keep publication credentials absent from tests; record exact rehearsal hashes and policy sources.

## Evidence and handoff
Not executed. Record exact commits/artifacts, commands/results, environment and remaining scope. Documentation is not implementation evidence or execution authorization.
