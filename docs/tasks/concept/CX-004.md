# CX-004 — Design actions, source operations and test-data workflows

## Outcome
The concept explains how a UI action uses a source operation and how the same contract supplies test data.

## Baseline and scope
Extend the [Data Sources model](../../concepts/companion/DATA-SOURCES.md) with contextual action forms and scenario authoring. Coordinate schema/provider decisions with SH-008/SH-009/SH-015 without implementing private native adapters.

## Acceptance criteria
- [ ] Actions declare trigger, input, validation, operation, success, error and feedback/navigation; labels never stand in for missing behavior.
- [ ] Sources, operations, DTO/entity shapes and per-surface usages remain distinct; mapping and synchronization are not inferred.
- [ ] Each source's test mode, seed/clock/locale, counts, constraints and edge scenarios are editable and previewable.
- [ ] Destination, mock-versus-real behavior, unsupported generators, collisions and reset ownership are understandable before a simulated apply.

## Verification
Use vault, API and logical-database design fixtures, missing mappings, write acknowledgements, invalid constraints and empty/error scenarios. Verify no network, native write or production-provider success is fabricated by the concept.

## Evidence and handoff
Not executed. Deliver interaction/schema decisions and scenario evidence; generic provider implementation remains SH-009/SH-010 and native integration CP-006.
