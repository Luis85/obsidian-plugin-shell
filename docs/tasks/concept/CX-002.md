# CX-002 — Refine design-only onboarding and lifecycle navigation

## Outcome
The concept makes project design useful on its own and clearly explains optional transition to implementation.

## Baseline and scope
Retain [one vault/one project](../../concepts/companion/SINGLE-VAULT.md). Explore the proposed Overview/Design/Code/Verify/Runs hierarchy without deleting capabilities. Include first-time and experienced-author minimal routes; no native conversion in this task.

## Acceptance criteria
- [ ] Start designing asks only essential identity/brief information; missing external tools do not block design or produce permanent failure badges.
- [ ] Companion installation, optional template preparation, generation, build, test deployment and manual enablement are clearly different actions.
- [ ] Returning users resume the same project and drafts; no second-project launcher or external source-root default returns.
- [ ] A dismissible/resumable tour explains real actions without fabricating completed work or trapping focus.

## Verification
Exercise design-only, minimal boilerplate, interrupted setup and returning-project scenarios in the concept. Use formative user review and keyboard/narrow-pane walkthroughs; report observed findings rather than assumed usability scores.
