# CX-005 — Develop the design-system authoring concept

## Outcome
Users can understand and review the designed plugin's typography, spacing, sizes and semantic styling, including Markdown/HTML export expectations.

## Baseline and scope
Build a concept UI over the proposed shared token model from SH-007. Retain host-theme inheritance and distinguish the consumer's design system from the companion's own interface. This is continuing feature work, not a declaration of native delivery.

## Acceptance criteria
- [ ] Token groups, aliases, defaults, overrides and theme variants have clear editing/validation behavior and concrete component examples.
- [ ] Markdown and HTML preview represent the same selected design-system revision; export scope and unsupported tokens are visible.
- [ ] Invalid values/alias cycles retain the draft with actionable errors; editing does not silently restyle unrelated host content.
- [ ] Fonts are references/configuration only; no automatic remote downloads or font binaries enter exports.

## Verification
Exercise default/custom tokens, missing aliases, long labels, light/dark preview, invalid drafts and export consistency. Record which exports are genuine browser artifacts versus simulations of later native file operations.

## Evidence and handoff
Not executed. Deliver UI contract, token/export fixtures and actual concept tests. Shared exporter behavior belongs in SH-007; native feature integration belongs in CP-007.
