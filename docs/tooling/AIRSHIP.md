# Optional Airship integration

Every generated plugin and clickdummy project has a source-backed browser preview: `npm run dev:preview`. It uses the actual generated Vue pages/components and synthetic read adapters, not a second renderer. Native host behavior and unimplemented business operations are not simulated as accepted functionality.

## Enable and use

```sh
node shell.mjs new ../my-project --starter quick-capture --airship --yes
cd ../my-project
npm ci
node shell.mjs airship install --yes
npm run dev:preview
# A second terminal in the same project:
node shell.mjs airship start --yes
```

Existing projects: review `node shell.mjs airship enable`, then apply with `--yes` or `--apply <reviewed-hash>`. Use `--agent claude|codex|opencode`, `--target-port 5173`, and `--port 5174` on enable to select the backend and distinct ports. Setup accepts `--input project.json --airship` or `--blank --airship`. Interactive creation/setup asks before opting in. `--no-airship` explicitly disables an imported choice.

Preview defaults to `http://127.0.0.1:5173`, Airship to `http://127.0.0.1:5174`. Start the preview first. Occupied ports fail rather than silently selecting another application. Use the surface toolbar or `#surface=<id>`; authored route paths remain metadata, not an invented application router.

`airship status` is read-only. Install, start and third-party doctor are separate operations requiring `--yes`. Importing or generating data does not install or start anything. No agent is installed or signed in automatically, no vault is opened, and no plugin is enabled. Provider credentials belong to the chosen agent, not project JSON. Provider execution can cost money and edit files. Review a clean Git baseline before editing.

## Project JSON

This optional top-level fragment belongs in a full **v6** project document:

```json
{
  "tooling": {
    "airship": {
      "enabled": true,
      "agent": "claude",
      "targetPort": 5173,
      "port": 5174
    }
  }
}
```

Omission means disabled. Frozen v1-v5 inputs remain unchanged unless explicitly opted in, which migrates to v6. The current Companion authoring composition preserves tooling on import/export; the retained v5 HTML/JSON is unchanged. `node shell.mjs schema` exposes `projectTooling`. Ports are integers from 1024 to 65535 and must differ. Unknown settings, command strings, hosts, permission flags and agent paths are rejected rather than ignored.

The pinned CLI is `@airshiplabs/cli@0.3.0`, installed only in ignored `.airship-tooling/`, outside application dependencies/lockfiles. Upstream source was inspected at [1063ba0](https://github.com/0xnyn/airship/tree/1063ba0002e33b2e19de586f2330b4356e51e8f5). Compatibility is version-qualified, not a guarantee about future upstream changes. The first explicit install resolves the CLI's transitive dependencies into its isolated lockfile.

## Source and safety contract

The [Vue resolver](https://github.com/aidenybai/element-source/blob/ff11ad2a3c6131e2b4ce569c1911b6bcb1eeb582/packages/element-source/src/frameworks/vue.ts) recognizes `data-v-inspector`. The serve-only transform adds original file/line/column locations to authored Vue elements and component invocation sites. Vendor templates are excluded; metadata is not written into source, native builds or offline output. Shared production build settings are unchanged.

The launcher requires `airship.config.json` to match canonical tooling, discards inherited `AIRSHIP_*` overrides, and enforces loopback, `--safe` and `--no-commit`. Configuration conflicts are explicit. Upstream safe-mode guarantees differ by agent: do not describe every backend as OS-sandboxed. Run only inside a trusted development checkout and inspect all resulting diffs.

Airship source edits do **not** automatically update project JSON. Regeneration preserves edited extension files when proposed generated bytes are unchanged; changed output produces an ownership conflict instead of overwriting. Managed design changes must be reconciled with intake/generation receipts. Enable/disable plans update settings and matching receipts/configuration, not authored Vue source.

`airship disable --yes` prevents future wrapper launches but does not terminate active sessions or delete installed tooling/configuration. Stop sessions with Ctrl-C. Source edits remain intact. Storybook stays independently optional: its existing scripts are preserved, and Airship does not require or launch its server. This change does not implement Storybook generation or claim its runtime has been qualified.

## Tests and acceptance

`npm run test:airship` covers strict/default-off settings, all 11 starters with enabled/disabled options for both compiler targets, custom source roots, independent optional scripts, reviewed plan staleness, process/argument/environment safety, Vue instrumentation and regeneration edit preservation/conflicts.

`node scripts/airship/qualify.mjs` is explicit scratch qualification under `reports/airship-qualification`: independent generated install/build, pinned upstream CLI, actual Vue source resolver, HMR, JSON export, private-file negative controls, and the Airship canvas proxy. It does not submit an agent prompt. The workflow records the exact source reference, observations and screenshot. AI-provider editing, native Obsidian acceptance and Storybook runtime acceptance remain separate.
