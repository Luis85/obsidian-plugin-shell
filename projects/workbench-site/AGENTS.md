# Agent instructions: Workbench

This is a standalone Astro website (template `project-page`). Work in this folder as if it
were its own repository.

## Commands

- Use Node 24.21.0 (`.nvmrc`) and `npm ci` with the exact `package-lock.json`. Do not run
  `npm install` unless you are deliberately updating a dependency, and pin versions exactly.
- `npm run check` is the gate: it builds the whole site. Run it before you stop and report its
  actual output.
- `npm run dev` serves the site locally; `npm run preview` serves the built `dist/`.

## Content

- Collection data lives in `src/data/collections/<name>.json`. These files are generated by
  `node bin/app site collections` in the Workbench shell from Obsidian Bases files. Never edit
  them by hand; change the notes or the `.base` view and regenerate them.
- `src/content.config.ts` registers each snapshot as an Astro content collection. Pages read
  records with `getCollection` (through `src/lib/collections.ts`).
- Pages must keep building with zero collections and must show an empty state for a missing
  or empty collection.

## Quality

- Keep pages accessible: one `h1` per page, headings in order, the `header`/`main`/`footer`
  landmarks of `src/layouts/SiteLayout.astro`, a `caption` on every table and tables inside the
  `.table-scroll` region, so nothing scrolls horizontally at 360px width.
- Keep the site static (`output: 'static'`). Do not add analytics, remote fonts or client
  scripts without a reviewed reason.
- Do not reach outside this folder: no imports from `../`, no `file:` dependencies.
