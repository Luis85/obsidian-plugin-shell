# Facilitation prompts

Pick the prompts that fit; never paste the whole list. Offer examples and a recommendation with each question so the user can react instead of starting from a blank page.

## Round 1: problem and people
- What happens today that should not? Walk me through the last time it happened.
- Who feels it most? Who else is affected (reviewers, collaborators, future self)?
- What would be observably different if this worked? How would you notice in a week?
- Is this an Obsidian plugin, a web app, a CLI, or are you not sure yet? (Hint only; the starter is chosen later.)

## Round 2: jobs and context
- Phrase the core job as "When ..., I want to ..., so I can ...". Is there a second, competing job?
- Where does the user start (a note, a command, a file type, a sidebar)? Where should they end up?
- What data is involved, and where does it live (Markdown notes, plugin data, files, nothing persistent)?

## Round 3: options (diverge)
- Generate at least three distinct directions, for example: a command-only flow, a dedicated view, a file-backed editor, an inline enhancement. Include "the smallest thing that could work" and "do nothing / use an existing tool".
- For each: what it is great at, what it gives up, and the first screen or command the user would see.
- "How might we ..." reframes for the hardest constraint.

## Round 4: risks and limits
- Which assumption, if wrong, makes the whole idea pointless? How cheaply can a prototype test it?
- What must never happen (data loss, overwriting notes, network calls, accounts)?
- What is explicitly out of scope for the first version?

## Converge
- Score the options against the outcome and the riskiest assumption; recommend one, and let the user choose or combine named elements.
- Restate the chosen direction in two sentences and list open questions. Material changes later reopen the PRD.
