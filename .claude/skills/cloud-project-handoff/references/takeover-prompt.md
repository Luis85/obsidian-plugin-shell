# Takeover prompt template

Copy the fenced block into `<id>-TAKEOVER.md` in the scratchpad. Replace every placeholder with a fact verified in this session. Never copy a value from this template's examples, and never claim a result that was not run. No angle-bracket placeholder may remain in the delivered file.

| Placeholder | Value |
| --- | --- |
| `<id>` | Plugin ID, also the zip and JSON base name |
| `<name>` | Display name |
| `<author>` | Author |
| `<target folder>` | Folder on the user's machine, for example `C:\Projects\delivery-management` |
| `<origin>` | `starter <starter>` or `companion export` |
| `<examples step>` | `The framework's example features were then removed with npm run examples:remove.`, or `The framework's example features are still registered.` |
| `<view label>` / `<view slug>` | Entry view the ribbon icon opens |
| `<first feature>` | The first feature the user named |
| `<commits>` | `git log --oneline` of the generated project, one per line, oldest first |
| `<cloud results>` | Real `npm ci` / `npm run verify:project` results and the `addRibbonIcon` count from `dist/main.js` |
| `<node version>` / `<npm version>` | From the generated project's `.nvmrc` and `packageManager` |

```text

- `<id>.companion.json` is the companion project file (schema 6) the project was generated from. Keep it; it's the design source.
- `<id>-TAKEOVER.md` is this prompt.

## Background
- It was generated by plugin-shell (Workbench) with `node bin/app new --from <id>.companion.json --install` (<origin>). <examples step>
- Plugin: id `<id>`, name "<name>", author <author>.
- Boilerplate: one ribbon icon, "<view label>", opens one view with screen slug `<view slug>`. The view is declared in `src/plugin/generated/domain/screens.ts` and wired in `src/plugin/generated/bootstrap/install.ts`. There's also a settings tab, and `src/plugin/main.ts` only calls `initializeProject`.
- Expected git history in the unpacked project:
<commits>
- Cloud results: <cloud results>. It has not been loaded in a real Obsidian vault yet.

## Steps
1. List the folder. Extract the zip into a temporary folder, then move the contents of its inner `<id>/` folder, including the hidden `.git`, `.claude` and `.agents` folders, into `<target folder>`. The project root must be this folder, not a nested `<id>\<id>`. Keep `<id>.companion.json`. Move the zip and `<id>-TAKEOVER.md` into a `_handoff` subfolder, and add `_handoff/` to `.git/info/exclude`.
2. Run `git status` and `git log --oneline`. Confirm the expected commits and a clean working tree. If line-ending noise appears on Windows, report it and do not commit anything to "fix" it.
3. Check the toolchain against `.nvmrc` and `packageManager`: Node <node version> and npm <npm version>. If they differ, tell me and suggest how to switch (nvm-windows, Volta or fnm). Do not install global packages without asking me.

6. Run `npm run check`, then `npm run verify:project`. Report the actual output: steps, pass/fail and timings. If something fails, diagnose it. Do not weaken thresholds or skip tests.
7. Confirm in the source that exactly the ribbon icon and view described above are registered.

## Constraints
- Do not run `npm run dev:obsidian`, `npm run setup` or any install into an Obsidian vault until I say so. When I do, use only the project-contained dev vault, never my personal vault.
- Do not add a git remote, push, or run `gh`/`az`.
- Do not start building features yet. The first feature will be: <first feature>, hosted in the "<view label>" view. Once everything above is green, propose briefly how you would start it, using the increment and ideation workflow in `AGENTS.md` (the `increment-handoff` skill). Then wait for my go-ahead.
```
